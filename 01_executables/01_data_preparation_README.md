# Part 1 of 3 — Data Preparation

`01_data_preparation.ipynb` · Pipeline position: **`[ 01 ] → 02 → 03`**

Everything that happens **before any model is trained**: data loading, the full exploratory data analysis, and the leakage-free feature engineering pipeline. Its outputs are the contract that notebooks 02 and 03 build on.

---

## What this notebook does

### 1. Data loading
The four competition CSVs (`train_features`, `train_labels`, `test_features`, `submission_format`) are located automatically (root folder or `train_test_data/`) and merged into a single working DataFrame of **59,400 pumps × 41 columns**.

### 3. Feature engineering (leakage-free)

All imputation medians, Top-50 vocabularies and target-encoding maps are fitted **exclusively on training rows**. The test set only receives the fitted values.

| Feature | Type | Purpose |
|---|---|---|
| `pump_age` | Derived | Infrastructure aging — older pumps fail more |
| `log_population`, `log_amount_tsh` | Transformed | Skew reduction |
| `region_fail_rate` | Target encoded | Regional failure risk |
| `qty_pay_combo` | Interaction | Water availability × payment behaviour |
| Top-50 reduction | Cardinality | `funder` / `installer` / `lga` → 50 values + `other` |

![Pump age distribution](images/fig_pump_age_distribution.png)

The transformation is written to **`feature_pipeline.py`** — a standalone module, generated by this notebook, that becomes the single source of truth. Notebook 03's live predictor imports the exact same function, so a pump entered in the Gradio interface goes through byte-identical preprocessing.
